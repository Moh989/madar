# مدار العالم — موقع Laravel مؤسسي

مشروع فعلي بـ Laravel 13 وBlade وCSS مخصص وJavaScript Modules وVite وMySQL. العربية افتراضية `/ar` والإنجليزية `/en`. نسخة التشغيل المحلية: http://127.0.0.1:8000/ar، الإدارة: `/admin`.

## تنزيل المشروع من GitHub

الملف التعريفي الخاص بالموقع محفوظ باستخدام **Git LFS** في `storage/app/private/company-profile.pdf`. ثبّت Git LFS ثم نفّذ:

```sh
git lfs install
git clone https://github.com/Moh989/madar.git
cd madar
git lfs pull
```

استخدم الاستنساخ مع Git LFS لضمان تنزيل ملف PDF كاملاً، ثم اتبع خطوات التثبيت أدناه. المستودع لا يتضمن `.env` أو كلمات المرور أو قاعدة التشغيل المحلية أو الاستفسارات؛ بنية قاعدة البيانات وبيانات التهيئة موجودة في Migrations وSeeders.

## المتطلبات والتثبيت

- PHP 8.3 أو أحدث متوافق مع Laravel 13 (اختُبر على PHP 8.5.7)، مع PDO MySQL وGD وmbstring وDOM وfileinfo وopenssl وctype وcurl وxml وtokenizer.
- MySQL 8.0+، Composer 2، Node 22.12+ أو 24 وnpm.
- إطار العمل المثبت والمقفل في composer.lock: Laravel 13.33.0. سياسة الإصدارات: https://laravel.com/docs/13.x/releases

```sh
composer install
npm ci
cp .env.example .env
php artisan key:generate
```

أنشئ قاعدة MySQL بترميز `utf8mb4` ومستخدماً مخصصاً بصلاحيات على قاعدة الموقع فقط. اضبط `DB_HOST`, `DB_PORT`, `DB_DATABASE`, `DB_USERNAME`, `DB_PASSWORD` في `.env`، ثم:

```sh
php artisan migrate --seed
npm run build
php artisan admin:create
php artisan serve --host=127.0.0.1 --port=8000
```

للتطوير بتحديث الأصول المباشر، شغّل `npm run dev` في نافذة إضافية. لا يحتاج التشغيل بعد البناء إلى خادم Vite.

## أول مدير

`php artisan admin:create` يطلب الاسم والبريد وكلمة مرور مخفية من 14 حرفاً على الأقل مع التأكيد. لا يوجد حساب افتراضي ولا كلمة مرور مثبتة في المصدر. لا يوجد تسجيل عام. `is_admin` وحده يمنح صلاحيات الإدارة، وتُحمى جميع مسارات الإدارة به.

## قاعدة التشغيل المحلية المسلّمة

شُغلت قاعدة MySQL مستقلة للمشروع على `127.0.0.1:3307`، ومجلد بياناتها `storage/mysql`، ومقبسها `/tmp/madar-mysql.sock`. أُنشئ مستخدم تطبيق وكلمات مرور عشوائية محفوظة فقط في `.env` وملف محلي محمي `storage/mysql-admin.cnf`، وجميعها مستبعدة من Git. لا تستعمل هذه القاعدة المحلية كإعداد إنتاج. قاعدة MySQL العامة الموجودة على الجهاز لم تُعدّل بياناتها.

عند توقف الخادم المحلي، تشغيله مجدداً:

```sh
mysqld --no-defaults --datadir="$PWD/storage/mysql" --socket=/tmp/madar-mysql.sock --bind-address=127.0.0.1 --port=3307 --mysqlx=OFF
```

في بيئة أخرى استخدم قاعدة MySQL جديدة بإعداداتك. جميع البنية في Migrations؛ لا يلزم نسخ مجلد البيانات المحلي.

## المحتوى والإدارة

- `pages`, `sectors`, `projects`, `news`, `slides`: حقول JSON منظمة حسب `ar` و`en` للعناوين والأوصاف والنصوص وSEO والنصوص البديلة، وحالة نشر وترتيب وإظهار.
- `media`: صور مع مصدر وترخيص وأبعاد ونص بديل. علاقات الصور الأساسية `media_id`، وقطاع المشروع `sector_id`، والاستفسارات مرتبطة بالقطاعات.
- `settings`: بيانات الاتصال، القوائم وترتيبها، النصوص العامة، الاسم الإنجليزي القانوني، ونسخة السلايدر المنشورة.
- `inquiries`: الطلب ومرجعه وحالته وملاحظات المتابعة وحالة محاولة إشعار البريد.
- حالات الاستفسارات: جديد، قيد المتابعة، مغلق.
- إضافة/تحرير/معاينة وحذف القطاعات والمشاريع والأخبار والشرائح؛ لا تُحذف الصفحات الأساسية ولا تُغير مساراتها.
- الصور: رفع JPEG/PNG/WebP حتى 8MB و4000×4000، إعادة ترميز إلى WebP، أسماء UUID، تخزين خاص، وتقديمها كصور فقط مع `nosniff`. لا SVG أو برامج مرفوعة.
- صفحة «الإعدادات والقوائم» تتيح ترتيب/إخفاء الروابط، وتحرير نصوص الأقسام العامة باللغتين. صفحة «الصفحات» تدير محتوى كل صفحة وSEO.
- السلايدر: حفظ مستقل كمسودة. زر «نشر الشرائح الأربع» يتحقق من العدد، الصورة، عنوان ووصف وزر ونص بديل باللغتين، وصلاحية الرابط الداخلي إلى محتوى منشور، ثم ينشر نسخة كاملة داخل transaction. تعديلات المسودة لا تغير السلايدر العام. يمنع حذف/إخفاء قطاع مرتبط بالسلايدر المنشور حتى تحديث روابطه.
- المحتوى نص عادي آمن؛ تُحفظ الأسطر وتُرمز المخرجات. لا يُقبل HTML خام.
- المشاريع والأخبار خالية في التهيئة، وتختفي أقسامها وروابطها عند عدم وجود محتوى منشور. لا تتضمن التهيئة مشاريع أو عملاء أو إحصاءات تجريبية.
- سياسة الخصوصية مسودة موسومة للإدارة فقط؛ لا يظهر رابطها حتى المراجعة والنشر.

## عرض الملف التعريفي

المجلة على `/ar/company-profile` و`/en/company-profile` تعرض صفحات الملف التعريفي الـ17؛ صفحة واحدة في كل نقلة على الحاسوب والجوال، مع تقليب ورقة منحنية ثلاثي الأبعاد يتبع السحب بالماوس واللمس، والأسهم والفهرس والتكبير وملء الشاشة. السحب القصير يعيد الورقة إلى موضعها، ويظل التمرير العمودي متاحاً على الجوال. وضع تقليل الحركة يلغي تأثير التقليب. يعمل التنقل الأساسي أيضاً دون JavaScript. صفحات WebP داخل `public/images/profile-page-*` والفهرس والنصوص في `resources/profile.json`.

نسخة PDF الخاصة بالموقع بعد حذف الهاتف واختصار العنوان في `storage/app/private/company-profile.pdf`، وتُنزل عبر مسار `company-profile/download`. انقل هذا الملف الخاص مع أصول الصفحات عند النشر (ملف PDF مستثنى من استبعاد storage ومحفوظ عبر Git LFS؛ نسخة التسليم المضغوطة تتضمنه أيضاً). لا يُحمّل PDF الكبير أثناء القراءة؛ صور الصفحات تُحمّل تدريجياً. عند غياب ملف الموقع تُخفى روابطه ويُعاد 404.

نصوص قصة الشركة ورؤيتها ورسالتها وقيمها قابلة للتعديل من الإعدادات ← النصوص العامة وأقسام الرئيسية وعن الشركة (مفاتيح `about_*`). المقدمة والعنوان من إدارة الصفحات. عنوان المقر المختصر هو العراق، بغداد، الداوودي؛ الهاتف محذوف من إعدادات الشركة والواجهة وبيانات Organization ونسخة PDF الخاصة بالموقع. الملف المرفق الأصلي `website_profile.pdf` محفوظ دون تعديل خارج مجلد الويب.

اختبارات هذه الإضافة: `php artisan test --compact tests/Feature/ProfileTest.php` و`node tests/Browser/profile.mjs` مع تشغيل الموقع محلياً.

## البريد والنماذج

اضبط في `.env`:

```dotenv
MAIL_MAILER=smtp
MAIL_HOST=your-smtp-host
MAIL_PORT=587
MAIL_USERNAME=
MAIL_PASSWORD=
MAIL_FROM_ADDRESS=your-approved-sender
MAIL_FROM_NAME="مدار العالم"
INQUIRY_NOTIFICATION_EMAIL=your-approved-recipient
```

أكمل إعداد TLS حسب مزودك وإعدادات Laravel `config/mail.php`. الطلب الصحيح يُحفظ أولاً في MySQL، ثم يحاول التطبيق إرسال إشعار لا يحتوي بيانات الطلب الشخصية، مع مرجع ورابط الإدارة. تأكيد الزائر يؤكد الحفظ فقط. إذا فشل SMTP يبقى الطلب محفوظاً بحالة `failed` للإشعار؛ وإذا غاب المستلم تكون الحالة `not_configured`. التهيئة المحلية تستخدم `log` بلا مستلم، فلا ترسل بريداً خارجياً.

النماذج محمية بـCSRF، تحقق خادمي، حقل مصيدة، وأربعة طلبات في الدقيقة لكل IP. تسجيل الدخول محدود بحسب البريد وIP مع حد إضافي للـIP، وتُجدد الجلسة بعد الدخول وتُبطل عند الخروج.

## التشغيل والنشر

1. جهّز PHP-FPM وMySQL وNginx وشهادة HTTPS ونطاق الشركة.
2. اجعل document root هو `public/` فقط. المثال في `deployment/nginx.conf` وقيود PHP في `deployment/php.ini`.
3. اضبط `APP_ENV=production`, `APP_DEBUG=false`, `APP_URL=https://your-domain`, `SESSION_SECURE_COOKIE=true` وبيانات MySQL وSMTP الحقيقية. لا تستخدم خادم Artisan في الإنتاج.
4. `composer install --no-dev --optimize-autoloader` و`npm ci && npm run build`.
5. `php artisan migrate --force`؛ شغّل التهيئة مرة أولى فقط عند الحاجة. التهيئة idempotent ولا تستبدل المحتوى الموجود.
6. `php artisan config:cache && php artisan route:cache && php artisan view:cache`.
7. امنح مستخدم الويب الكتابة إلى `storage` و`bootstrap/cache` فقط. لا يلزم `storage:link` للصور؛ تُقدّم من مسار الصور الآمن.
8. أنشئ المدير تفاعلياً. ضع نسخاً احتياطية مجدولة لقاعدة البيانات و`storage/app/private/media` واحتفظ بـ`APP_KEY` بأمان.
9. أكمل مراجعة سياسة الخصوصية والاسم الإنجليزي والمحتوى المؤسسي قبل فتح الموقع للجمهور، واختبر SMTP فعلياً.

خريطة الموقع `/sitemap.xml` تتضمن المنشور فقط باللغتين. لوحة الإدارة والمعاينات وكل بيئة غير إنتاجية ترسل `X-Robots-Tag: noindex, nofollow`؛ `/robots.txt` يمنع فهرسة البيئة المحلية. بيانات Organization لا تتضمن إلا الاسم وURL وبيانات الاتصال الواردة في الملف. canonical وhreflang وOG تولّد من `APP_URL` الموثوق.

لم يُنشر الموقع على نطاق عام: المشروع جاهز لنشر PHP/MySQL، ولا توجد بيانات استضافة إنتاجية ضمن المهمة.

## الاختبارات

```sh
php artisan test
npm run build
```

اختبارات Laravel تستخدم SQLite معزولة في الذاكرة ولا تمس بيانات MySQL. فحص المتصفح فعلي على MySQL المحلي؛ التقرير في `docs/browser-report.json` و`docs/QA.md`. لقطات الرئيسية داخل `docs/screenshots/`.

لإعادة التقاط الصور: `npx playwright install chromium` ثم `node tests/Browser/capture.mjs` بعد تشغيل الموقع. `tests/Browser/verify.mjs` هو فحص تكاملي يتطلب حساب QA مؤقتاً عبر `/tmp/madar-qa-credentials.json` ويتعمد إنشاء استفسار وخبر وصورة اختبار؛ لا تشغّله على الإنتاج. اختبارات PHPUnit لا تتطلب هذا الحساب.

## ما ينتظر بيانات الشركة

- اعتماد الاسم الإنجليزي القانوني وصياغة المحتوى التسويقي وترجماته.
- مراجعة بيانات الاتصال المستخرجة من الملف التعريفي، وتزويد بريد SMTP ومستلم الإشعارات والنطاق والاستضافة.
- اعتماد سياسة الخصوصية، مدة الاحتفاظ بالطلبات، وآلية ممارسة الحقوق والحذف.
- صور الشركة الأصلية وحقوقها؛ ومشاريع وأخبار معتمدة إذا رغبت الإدارة بإظهارها.
- الرؤية والرسالة والقيم وروابط التواصل الاجتماعي اختيارية؛ لا توجد روابط وهمية.

الأصول والصور وأوامر توليدها والتراخيص موثقة في `docs/ASSETS.md`.
